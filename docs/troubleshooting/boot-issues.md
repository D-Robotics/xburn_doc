# 启动异常

烧录完成、设备重新上电后，若长时间无显示输出或启动失败，按本篇排查。启动异常通常与烧录模式选择、启动盘配置、镜像完整性相关。

:::info 先看串口
启动异常排查高度依赖串口日志。若尚未配置串口，先按 [各平台环境准备](../environment/windows-setup) 配好串口控制台，再按本篇进行排查。
:::

## 长时间无显示输出

**问题现象**：设备上电后长时间没有显示输出（2 分钟以上）。

**原因分析**：可能启动异常，需通过串口日志判断设备是否正常启动、卡在哪一阶段。

**解决方案**：

1. 通过串口线连接设备，打开串口控制台（波特率 `921600`，RDK X5 选 `115200`，见各平台环境准备）。
2. 重新上电，观察串口是否有启动日志输出。
3. 若串口完全无输出，检查供电与启动盘选择开关是否正确。
4. 若串口有输出但卡在某阶段，根据日志内容判断（如卡在 uboot、卡在内核加载等）。

## 启动盘选择错误

**问题现象**：烧录完成后无法启动，串口提示找不到启动介质。

**原因分析**：部分型号的启动盘需通过拨码开关选择，拨错位置会导致设备不从已烧录的介质启动。

**解决方案**：以 RDK S100 为例，需将 SW3 开关拨至从板载 eMMC 启动（暂不支持从 M.2 NVMe 固态硬盘启动）。各型号的具体启动盘选择方式，见对应产品烧录文档与硬件介绍。

## 烧录模式未退出

**问题现象**：烧录完成后设备无法正常启动，仍停留在烧录模式。

**原因分析**：DFU 烧录需手动设置设备进入 DFU 模式，烧录完成后需退出 DFU 模式恢复为正常启动模式。

**解决方案**：DFU 烧录完成后，关闭电源，将烧录开关拨回正常启动位置，再重新上电。具体开关操作见各产品烧录文档。

## 备份镜像烧录失败

**问题现象**：用备份的镜像重新烧录时失败。

**原因分析**：备份镜像文件名带 `_backup` 后缀，与烧录指定区域时要求的原始镜像名不一致。

**解决方案**：将备份镜像文件名中的 `_backup` 去掉，改回烧录指定区域时的原始镜像名（如 `miniboot_flash_backup.img` → `miniboot_flash.img`）。

:::warning 整盘备份耗时
数据备份耗时较长，耐心等待备份结束，中途断电会得到不完整的备份镜像。
:::
